# GR308 三卡并行 MTP1 / Graph32 测试设计

## 目标

在 `192.0.2.11` 上复用既有 Qwen3.6-27B 测试合同，对三张独立物理 GR308 卡并行执行 3072 输入、1024 输出、64 请求、C1/C16 测试。

- 物理卡 0（逻辑设备 0、1）：Qwen3.6-35B-A3B，TP2，BF16，MTP1，Graph capture size 32。
- 物理卡 1（逻辑设备 2、3）：Qwen3.5-9B，TP2，BF16，MTP1，Graph capture size 32。
- 物理卡 2（逻辑设备 4、5）：Qwen3-30B-A3B，EP+TP2/BF16，Graph capture size 32，因无原生 MTP 权重而运行 baseline，并明确记录 MTP 不适用。
- 物理卡 3（逻辑设备 6、7）：保持空闲，作为安全余量，不自动调度其他模型。

## 隔离与执行

以现有 `run_goal_model.py` 为基线创建本轮专用并发 runner，不覆盖旧脚本。每个任务使用独立容器名、端口、CPU 集和结果目录。启动前只做一次全机空闲与健康准入；运行中允许本轮三个已登记容器共存，但拒绝任何额外容器。

监控器按任务核对目标逻辑设备温度、显存、后端致命错误和容器存活，同时对全部八个逻辑设备执行健康查询。非目标设备允许由另外两个已登记任务使用；物理卡 3 必须保持 540 MiB 空闲基线。

## 测试合同

每个可运行配置先验证模型身份、容量与四项正确性，再依次执行 C1、C16。每档 64 请求，固定 seed，关闭 prefix cache，记录完整请求数、输出吞吐、TTFT/TPOT/ITL、MTP draft/accepted 计数、Graph 日志、遥测及停止后的显存释放状态。

Graph 配置固定为 `FULL_DECODE_ONLY`，捕获尺寸仅 `[32]`。MTP 配置固定为 `method=mtp, num_speculative_tokens=1`；30B 不注入虚假的 MTP 参数。

## 故障处理

单任务发生 OOM、设备锁死、温度超限、健康异常或容器退出时，只停止该任务并保留证据。任何全机设备健康异常都会触发全部本轮任务安全停止。不得重启主机、重载驱动、删除模型或清理其他用户数据。

## 完成标准

35B 与 9B 的 MTP1+Graph32，以及 30B 的 baseline+Graph32，均有 C1/C16 的 64/64 完整请求结果、正确性通过、证据文件齐全、测试后对应物理卡显存释放且全机健康。失败也必须保留完整失败原因，不能记为通过。
