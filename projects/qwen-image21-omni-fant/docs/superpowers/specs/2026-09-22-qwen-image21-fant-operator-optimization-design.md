# Qwen-Image-2.1 GR308 算子优化设计

## 目标

在 GR308 单卡双芯 TP2 环境中优化 Qwen-Image-2.1 DiT 的热点算子。当前序列
长度 4096 的单 Block 约需 0.604 秒，其中普通 SDPA 占约 0.485–0.489 秒。
本轮只进行真实 checkpoint 的单 Block 和单算子测试，不运行端到端图片生成。

## 范围

- BF16，TP2，逻辑设备 `fant:0` 和 `fant:1`。
- 序列长度 1024 和 4096。
- 首先优化注意力；随后测试 Norm、RoPE、门控和残差融合。
- 保持现有 Qwen-Image-2.1 权重、张量布局和 TP2 切分方式。
- 测试在一次性容器中执行，不重启设备，不停止其他设备上的服务。

## 候选路径

### 1. FANT 融合注意力

枚举运行时可用的 SDPA backend，测试显式 backend 选择、`torch.compile` 和
compiled `flex_attention`。同时检查当前厂商 vLLM/FANT 包中是否有输入布局兼容的
attention custom op。只有接口、语义和 mask 能精确匹配时才接入候选测试。

### 2. 分块精确注意力

若没有可用融合后端，使用分块 Q/K 和在线 Softmax 实现数学等价的 BF16 注意力。
该路径主要减少完整 attention score 的中间存储和显存流量。Python 循环或过多通用
kernel 可能降低速度，因此必须以实测决定是否保留。

### 3. 逐元素算子融合

在注意力候选完成后，测试 RMSNorm、LayerNorm、RoPE、门控和残差组合是否可通过
`torch.compile` 或已有 FANT custom op 合并。该阶段不得改变模型数学结构。

## 数据流

每个 rank 加载真实第 0 个 Transformer Block，并按现有 TP2 方案切分注意力头和
MLP 通道。固定随机种子生成输入。基线与候选接收同一输入，先完成数值比较，再执行
独立预热和计时。collective 由两个 rank 同步进入；计时前后执行设备同步和 barrier。

## 验收标准

- 每个候选至少预热 3 次，正式测试至少 10 次，报告中位数和分位数。
- 输出必须全部为有限值。
- 相对普通 SDPA 的 MAE 和最大绝对误差不得超过当前 BF16 TP2 的既有误差量级；
  默认门为 MAE 不高于 0.01、最大绝对误差不高于 0.25。
- 候选相对同进程基线至少加速 5%，才列为有效优化。
- 记录单算子耗时、完整 Block 耗时和峰值显存。
- 运行失败、后端不支持和数值越门均保留为失败证据，不计为优化结果。

## 执行顺序

1. 建立重复次数不少于 10 次的冻结 SDPA/Block 基线。
2. 枚举并测试 FANT 可用 attention backend。
3. 测试 compiled `flex_attention`；编译或执行失败时记录原因并退出该候选。
4. 测试分块精确注意力。
5. 测试逐元素算子融合。
6. 汇总数值、延迟、显存与失败证据，选择达到验收门的实现。

## 风险控制

所有实验使用短命容器。候选发生 PAL 断言、进程挂起或设备错误时终止对应容器，先检查
设备健康和既有服务状态；不执行设备 reset 或主机重启。当前 FHCCL 多进程退出问题继续
使用成功后 `os._exit(0)` 的既有规避方式。
